## 1. P0-1 私密正文被预填进「当下感受」输入框

- **根因**：`#mood-text` 的 `value` 直接取 `p.viewpoint` 里最后一条 `private` 的 `text`，每次 `render()` 都写一遍。遮罩状态只作用于"私密记录"页，没作用于输入框。
- **修法**：输入框改为只回填 `state.moodDraft`（本次会话新输入，切档案时清空）；`input` 事件写回 `state.moodDraft`；加一行说明"已保存的记录不会回填到框里"。私密正文**不再有任何路径**进入 `<textarea>`。
- **复验**：
  ```
  #mood-text value = ""（空）
  是否含第 1 条私密原文前 8 字 = false
  ```

## 2. P0-2 跨档案私密解锁残留

- **根因**：`[data-profile]` 的点击处理只重置 `state.sub`，`showPrivate` 保持不变。在 A 档案解锁后切到 B，B 的私密正文直接渲染。
- **修法**：切档案时重置**全部主体相关 UI 状态**：`showPrivate=false`、`metricPick=null`、`agentDraft=null`、`candidateOpen=false`、`moodDraft=''`、`trialsQuery=''`、`exportOpts.privateOn=false`、`lastExport=null`；同档案重复点击直接 return（避免无意义重渲染）。
- **复验**（真点 UI，非直接改 state）：
  ```
  陈女士 · 私密记录 → 点"我要看" → showPrivate = true
  点 .profile-item[1]（王先生）→ showPrivate = false
  #main 是否含王先生私密原文"还能撑几轮" = false
  ```

## 3. P0-3 就诊一页纸丢失代记标记

- **根因**：`buildVisitPrepSheet()` 返回值里没有 `recorder`/`recorderLabel`，而这两个字段在页面别处（顶栏、记录行）都在用——只是这个出口漏了。
- **修法**：`exits.js` 的 `buildVisitPrepSheet()` 增加 `recorder` + `recorderLabel`；`.print-head` 渲染成「记录人：女儿代记（家属代记，本人可能未逐条核对）」；非本人记录时明确写出"可能未逐条核对"。
- **复验**：
  ```
  陈女士 → recorder=patient,  label="本人记录"
  王先生 → recorder=caregiver, label="女儿代记"
  一页纸正文含"记录人" = true
  ```

## 4. P0-4 「应接受康复评估」

- **根因**：`app.js` 一行文案写的是肯定祈使句，而同页 notice 自己写着"不输出这类句子"。更根本的问题是**禁词测试只扫 `JSON.stringify(D)`，不扫模板文案**，20 词表也漏了"应/应当/需/务必/建议你"整类。
- **修法**：① 文案改为描述性转述（"提到…并讨论了康复评估（该指南原文为建议性表述；此处只记录这个议题存在，不转成对你的要求）"）；② 新增测试「模板文案不含指令式表述（K2）」，按**整类正则**扫 `app.js` + `exits.js` + `demo/build-demo-data.mjs`，去掉注释后扫描，只允许 `「…」` 包裹的医生原话豁免；③ 顺带改掉上一版的"不输出『你应当去…』"——这句自身就命中，改成"只记录医生有没有提过"。
- **变异测试（证明这个测试真的会红）**：往 `app.js` 塞回 `'应接受康复评估；…'` →
  ```
  模板文案出现指令式表述：应接受 → 1 行；应当去 → 1 行
  # pass 11 / # fail 1
  ```
  还原后 `# pass 25 / # fail 0`。
- **复验**：全站文案对 `应接受/应当去/建议你/务必/必须去` 命中 = 0。

## 5. P0-5 折叠卡副作用错挂治疗线

- **根因（两层）**：① 代码：`p.local.find(l => l.complications)?.complications` 取"第一条带并发症的局部记录"，完全不按 `line.dateStart/dateEnd` 过滤；② 数据：第 2 线状态是"已换线"但 `dateEnd` 为空，于是这条线"永远没结束"，把第 3 线的记录也吞进来。
- **修法**：① 副作用改为从**本线时段内**的局部并发症 + `functionLog` 里 `domain='ae'` 的自述不适合并取；② 数据侧给第 2 线补 `dateEnd: '2026-07-14'`（换线日 = 下一线开始前一天），并新增两条只属于第 2 线的 AE 记录（手脚发红脱皮 / 家量血压 145/92）；③ 模板里"已换线/已结束却没有结束日"不再静默显示"进行中"，改显示"结束日未记录"。
- **复验**（展开王先生 3 条线）：
  ```
  第 1 线：无 + 说明（该阶段没有记录到）
  第 2 线：2025-12-10 手脚发红脱皮… | 2026-02-20 家里量的血压 145/92…
  第 3 线：2026-09-21 术后腹胀，第 3 天缓解。
  三条互不相同（unique = 3）
  ```

## 6. P0-6 导出默认含演示数据

- **根因**：`exportOpts.demoOff` 默认 `false`，注释写着"不能当默认值，否则演示看起来像坏了"。**默认值由演示观感决定，而不是纪律**——这是整条 P0 的实质。
- **修法**：① `demoOff` 默认改回 `true`（SPEC §4.2 / K5）；② 担心"看起来坏了"的正确解法是**解释这个空**，不是改默认值：新增 `.empty-state` 明确写「本原型全部记录都标了 in_use=1（演示数据），而导出默认排除演示数据——所以默认是 0 条。**这不是坏了，是纪律在起作用。**想看导出长什么样，取消勾选"排除演示数据"」；③ 顺手修掉评审指出的 P1-4 参数名不匹配（`demoOff` → `demoOn` 经 `optsFromUI()` 归一）与 P1-5 日期范围不生效。
- **复验**（真点 UI）：
  ```
  默认：            pill = 约 0 / 36 条   空态 = true
  取消"排除演示数据"： pill = 约 31 / 36 条  空态 = false
  点生成：          toast = "导出快照已生成：30 条 · 已排除 5 条私密"
                    结果卡 "上次生成的结果" = 显示
  再勾"包含私密"：   pill = 约 36 / 36 条
  起始日期改 2026-01-01：pill = 约 2 / 36 条（范围真生效）
  ```
