## 二、照抄样板的产品要求（不许按比例缩减）

- 顶栏三段式 + AI 五态按钮（`AI 对话 / 正在连接… / 收起 AI 对话 / 打开 AI 对话 / AI 对话暂不可用`）＋独立「×」。
- 面板默认右侧：`businessWidth 0.65` / `AGENT_PANE.default 0.35` 互补，`assertPanelConfig()` 钉住；
  可拖（容器 rect 夹取、`role=separator`、键盘同精度、localStorage 读回过 clamp）；
  窄容器（<760px）覆盖式抽屉 ≤420px，splitter 不出现。
- 一图秀：单调三次插值（Fritsch-Carlson）、末点按 y 排 13px 避让、右端左锚定、
  事件竖虚线**上端止于 CY0-10**、分类序列只画节点不连线、关治疗节点不改曲线。
- 3D 卡整卡 180° 翻面，背面迷你折线；单点写「只有 1 次记录，暂不连线」；分类记录不翻不连线。
- 字号三档 1 / 1.15 / 1.32；SVG 内文字不随档位；溢出判 `body.scrollWidth`。
- 页脚贴底（`min-height:calc(100vh - 32px)` + `flex:1`）；`[hidden]{display:none!important}`；
  图标 key 走别名兜底；内联 svg 必须给宽高。

## 三、硬约束（每条带错误来源）

### 数据层

- 复合主键表裸 `SELECT` 必须 `ORDER BY rowid`；手写倒序数组只 `ORDER BY ord` 不叠 `DESC`。
  *来源：家族通用，多个仓踩过。*
- 可选字段显式写 `null`（读模型按 `=== null` 分支）。
- `using` 是 SQLite 保留字 → 列名 `in_use`。
- 每一节 `{title, rows}` 都必须有对应 `*_title` 列。*来源：家族发布前发现漏列，走 ALTER 追加。*
- 分类指标 `dec IS NULL` 且 `kind ∈ {grade,qual}`。
- 化验记录必须有 `ref_low` / `ref_high` 两列（可空）；写入时先挡 `null/undefined/''` 再 `Number()`
  —— `Number(null) === 0` 会把「没填上限」变成「上限是 0」。*来源：家族三个不同地方踩过。*
- `events` / `docs` / `candidates` 在快照里是**定长数组**；生成器 `assemble()` 的中间量必须解构掉。
- 化验/体征 2–4 周一点延续到今天；影像按**真实频率**，不加密。

### 前端

- 面板参数唯一来源 `lib/layout.js`；客户端里不许出现第二个 `0.65` / `0.35`。
- `apiBase` 不含 `/api`，调用写 `${apiBase}/api/xxx`；守卫只禁交界重复 `/api/api`（`/(^|/)api$/`），
  不许 `includes('/api')` 一刀切。*来源：GBM 踩 4。*
- 演示数据只有一个来源；原型不单独改 `demo-data.js`，开发版不另建 seed 脚本。
- 启动期校验失败渲染错误横幅，**禁止裸 throw 白屏**。

### 工程

- 迁移只增不改；所有 INSERT 写显式列名 + 显式问号数。
- `lib/version.js` 是生成物，不手改；`--check` 比对时**忽略 commit 行**，再用
  `git merge-base --is-ancestor` 核真实性（判退出码 `status === 0`，不判空输出）。
- 所有 git 成败看退出码。

### 医学口径（肉瘤专属，本仓红线）

1. **分级 ≠ 分期 ≠ 亚型，三者不许互推、不许合并显示。**
   FNCLCC 分级（G1/G2/G3，由分化/核分裂/坏死三成分打分）、TNM 分期（且按部位分表）、
   病理亚型，是三套东西。界面三个词分开摆，未回报的显示「未回报」，不猜。
   *来源：肾癌分型/分期/分级三词混用的教训（DIFF-MATRIX §三）；肉瘤分期还按部位分表，混用风险更高。*
2. **部位只做记录，不推导分期。** 肢体/躯干/头颈、腹膜后、内脏、眼眶的分期表不同，
   产品只记「肿瘤长在哪」（病理/影像原文），不替用户算期别。
3. **切缘状态（R0/R1/R2）只抄病理原文，不解释「切干净了没有」。** 这是判读。
4. **非计划切除只记事实，不评价当初的处置。** 界面可陈述「在某院做过一次切除，
   病理于 X 日回报为肉瘤」，**不出现「当初不该切」「这样切不规范」**这类句子。
5. **不计算生长速度、不设「该手术了」阈值。** 影像大小按原文并列。
   *来源：肾癌 AS 契约；红线词出现在否定说明里也会被 `check-wording` 判越界，最终改文案而非加豁免。*
6. **转移部位只记报告原文写的部位**，不推导「肉瘤主要血行转移至肺」这类规律。
7. **功能量表（MSTS / TESS / LEFS）不给分。** 这些是医师评估或患者自评量表，分数含义属医学判断。
   工作台只记患者自述的「哪些动作现在做不了」（事实），不打分、不评「功能好/差」。
8. **界面出现的每个药名标「获批状态未核实」。** NMPA 获批 ≠ FDA 获批，本轮未逐条核实。
   *来源：肾癌 P1-3。*
9. **×ULN 型指标用这张化验单自带的 `ref_high`**；缺了返回 `needsUln` + 虚线徽章「需参考上限」，
   **绝不拿成人通用上限凑倍数**。一句话记法：**下限可以借，上限不能借。**
10. **提醒属第②层**，判据只有一条：触发条件来自用户自己的记录或日期（可），
    还是来自医学阈值判断（不可）。写法三样缺一不可：陈述事实 + 指明这是谁的标准 + 指向医生。

## 四、本轮明确未做（不许在验收里算通过）

- 装机（M7）与市场投稿；患者/家属访谈（**0 访谈，场景全假设**）。
- CSCO / NCCN 软组织肉瘤指南原件（未取得，页码一律待核）→ 因此 G1 出处层、
  **G2 节奏层、G3 分级层本轮均不做**。
- 中国获批药物清单逐条核实。
- ChiCTR / ICTRP 采集通道（视 M3 实际结果如实记录终态）。
- 照护者代记（双主体只做标记，不做权限模型）。
- AI 面板拖拽（M6+ 事项）。
- **私密内容三出口**（家族 26 号 §4.3）：`visibility` 字段、可见性选择、一图秀/摘要/导出各自过滤，**本轮全未做**。
  原型也没有摘要与导出功能，所以本轮不存在「私密内容被泄漏」的实现风险，但契约确实没承接。
  逐条现状见 `docs/SPEC.md` §「私密内容的三个出口」；M6 做「情绪与照护者」页时必须一并落库。
- 任何切缘、复发、预后、方案优劣的判读——**一句都不生成**。
