## 1. 问题、用户与最小闭环

### 1.1 问题

软组织肉瘤（STS）患者在信息上有三个**结构性的**困难，而不是"资料不够多"：

1. **亚型碎片化**：STS 的亚型高度碎片化（WHO 2020 第 5 版分 11 类、另单列未分化小圆细胞肉瘤；文献常引「约 70 种恶性亚型」，WHO 本身不设总数，见 `CLINICAL-DATA.md` §2）。公开中文信息几乎只到"软组织肉瘤"这一层，患者拿到"滑膜肉瘤""去分化脂肪肉瘤""上皮样肉瘤"这些词之后，**搜不到自己能用的那一层**。
2. **部位决定路径**：同一个亚型长在肢体、腹膜后、头颈，手术方式、放疗安排、复查影像、复发模式都不同（AJCC 第 8 版的分期组按部位分列，见 `CLINICAL-DATA.md` §3）。网上把"肉瘤"写成一种病，患者会把不同部位的方案混算。
3. **治疗是并行的**：手术（局部）、放疗（局部）、化疗/靶向（全身）、临床试验常常**同期进行**，不是"一线失败换二线"的单链。患者的真实记录是"我 3 月手术、4 月开始放疗、同时进了组"，而现有工具都按单链设计。

### 1.2 用户

| 用户 | 占比判断 | 主要任务 | 工作台给他的 |
| --- | --- | --- | --- |
| 术后随访期患者（肢体/躯干） | 多数 | 记复查、看影像报告、准备复诊 | 影像基线 + 复查日历 + 问题清单 |
| 腹膜后肉瘤患者 | 少数但最复杂 | 记多次手术、腹部影像、营养与肾功能 | 部位分轨 + 多次手术档案 |
| 晚期/复发换线患者 | 少数 | 记多条治疗线、试验、副作用 | 并行治疗轨道 + 换线原因原文 |
| 家属代记者 | 常见 | 替患者记、陪诊 | 代记标记 + 一页时间线 |
| 年轻患者（生育议题） | 少数 | 治疗前生育保存、亲密关系 | 私密生育线 |

### 1.3 最小闭环

```text
输入：一份病理报告（照片/PDF/手输）+ 一次影像报告 + 一次治疗事件
动作：AI 候选或手工录入 → 逐项核对 → 确认入事实层 → 挂到部位/治疗线
输出：一页时间线（亚型 + 部位 + 局部/全身轨道 + 基线影像 + 下次复查）
成功：患者能在 3 分钟内说清"我是什么亚型、做过什么、哪次影像是对照基线"
失败恢复：AI 说错 → 拒收零副作用 → 转手工；没资料 → 空态给"先记这一条"
```

## 2. 方案与 ADR

### ADR-1：为什么按「部位」而不是按「亚型」做一级导航

- 候选 A：按亚型分（滑膜/脂肪/平滑肌/上皮样…）。否决：约 70 个亚型无法做成导航；且患者往往**先知道部位、后知道亚型**。
- 候选 B：按治疗阶段分（术前/术后/复发）。否决：STS 的局部与全身治疗并行，阶段划分会把同期事件撕成两半。
- **选择 C：部位作为记录的属性（`site`），治疗按「局部/全身」两条轨道分页**。理由：部位决定复查影像与手术方式，是**记录维度**不是导航维度；局部/全身是**任务维度**，患者问"我手术之后还要放疗吗"和"我化疗到第几周期了"是两个不同问题。

### ADR-2：为什么不做自动分期

FNCLCC 分级需要分化/核分裂/坏死三项，AJCC 分期需要部位特异的分组表；两者都是**病理科与临床医生的判读结果**。工作台自动算 = 把医生任务伪装成患者功能（红线）。**选择：只存医生原文 + 出处，界面并列展示"报告写的"与"我记的"。**

### ADR-3：为什么影像不做趋势线

RECIST 需要目标病灶测量与阅片者判断，患者手里的报告只有文字描述。把"较前增大"画成折线 = 伪造数据。**选择：影像只做「基线锚点 + 原文并列对照 + 时间间距」，不做数值趋势。**

### ADR-4：宿主能力表（本机核验）

| 能力 | 官方合同 | 本机核验 | 替代路径 |
| --- | --- | --- | --- |
| 服务端注册 | `webServer.register` + `connection.requestRejection` | ✅ M0 静态契约检查通过（`check-host-contract`） | 无 |
| 客户端外壳 | `desktopWorkbenches.register` + `dsh-desktop-workbenches` inject | 🔧 模板已带，M5 接真链路 | 无 |
| 数据根 | `config.root` + `dshHomePath` | ✅ patch 已注入，服务端读取并建目录 | 缺省时空串=未接线（会显形，不静默） |
| 原生 AI 面板 | 右侧可拖/可隐藏/可按会话复用 | ⏳ 未接（M5） | 未接入时按钮显“未接入”，不自制聊天窗 |

合计 **11 一级 / 35 二级**（26 号下限：≥8 / ≥20；单条一级内二级 ≤6，最多的两条是 4）。与 cervical（12/…）、breast（8/27）的**一级名称一致率见 `DIFF-MATRIX.md`（实测）**。

### 3.2 明确不做的页面

- 「我的分期」独立一级：否决。分期是医生写的，且 STS 分期组依赖部位，独立成页会诱导患者自己算。改为「我的亚型 · 分级与部位」二级页。
- 「营养支持」独立一级：否决（与乳腺/肝不同）。STS 患者的营养问题集中在腹膜后术后与化疗期，并入「功能与康复」与「指标与报告」，不单列——**理由写在这里，不是漏了**。
- 「一图秀」独立一级：否决。STS 没有一条贯穿全病程的数值指标（不像 CML 的 BCR-ABL），强行做图会变成假趋势。影像与血象各自有页。

## 14. 三条结构性决定：指标卡 / 一图秀 / 试验匹配（2026-10-25 用户反馈后新增）

> 来源：用户看原型后的三条意见（原话）：
> ①「指标卡片没有看到有序，分系列，动态3d反转的内容」
> ②「一图秀需要增加指标选择窗口」
> ③「临床试验：这个疾病没有临床和病理/基因需要吗？如果有，参考下临床研究基本思路是个人基因病理ihc维护建档 - 搜索或者AI协助匹配 - 查询自带sqlitedb + 外部工具技能 -> 匹配结果，这个有个匹配指数和格式，脚手架特别加了。」

**这三条推翻了我此前的一个决定，必须记录**：ADR-3 原本写"STS 没有贯穿全病程的数值指标，因此不做一图秀"。用户明确要求一图秀，**决定作废并改为做**。理由修正为：STS 没有**单一**贯穿指标是对的，但正因为没有单一指标，多指标同轴（各自归一化、不可比）才更有用——患者问的是"这段时间里哪些数在动"。ADR-3 中"影像不做数值趋势"的部分**保留**（影像仍只做基线锚点 + 原文对照），因为那涉及判读，与此处无关。

### 14.1 指标卡（27 号：真 3D 翻面 + 分系列）

- **分系列**：按轨道分组，一张卡只属于一条轨（27 号 §5）。本癌种三轨：`血象`（能不能按计划继续治疗）/ `肝肾与心肌`（药能不能代谢、心脏受不受得住）/ `功能测量`（周径、步行距离这类自己量得出的数）。
- **有序**：分组顺序 = 轨道定义顺序，页面上不做第二处排序；同一轨内按指标名首次出现顺序。
- **3D 翻面**（27 号 §3 合同）：`perspective:1100px` + `preserve-3d` + `rotateY(180deg)`；外卡固定 **276px**；正面六段（类别眉题 / 指标名 / 最近值+原单位 / 与前次差值 / 一句边界说明 / 记录次数+日期+来源+翻转提示），背面只有趋势与依据。
- **状态存 key 不存 DOM**：`state.flipped = new Set([name])`；点击只改 `aria-pressed` 与隐藏面 `inert`，**不重绘**（重绘会打断 480ms 过渡，也会让"翻一张别的卡跟着复位"）。
- `prefers-reduced-motion` 下取消过渡但保留终态。
- 实测：5 张卡 → 10 个面；翻第一张后 `aria-pressed=true`、内层 `transform` 为 `matrix3d(...)`、其余 4 张仍 `false`、卡高仍 276。

### 14.2 一图秀（16 号：多指标 + 指标选择窗口）

- **指标选择窗口**：左栏列出全部指标，最多选 **4** 条（超出时拒绝并提示"先取消一条"）；每项显示最新值与单位；列表独立滚动。

### 14.3 试验匹配（35 号：建档 → 匹配 → 库 → 结论边界）

四段式，顺序不可换（35 号 §2）：

| 段 | 本项目落点 | 硬约束 |
| --- | --- | --- |
| ① 个人建档 | 「我的建档」：地区 / 亚型 / 分子检测 / 免疫组化 | 三态（已知 / 未测 / 本癌种无此项）必须可分辨；**未测不写成阴性**；不推断分型 |
| ② 匹配计算 | 「匹配结果」：每条试验一个指数 + 维度明细 + 缺口清单 | 未知维度**不进分母**；入排标准 / 生物标志阈值 / 年龄区间永不进计算；`index=null` ≠ 0 |
| ③ 试验库 | 「试验库」：通道终态（ready / 未取回）+ 条目 | `partial`/`timeout` 不降级成 ready；"0 条不代表没有研究"必须显形 |
| ④ 结论边界 | 三段都有 notice | 禁止"可以入组 / 符合入组条件 / 建议报名" |

**STS 的建档字段选择依据**（35 号 §4："病种里没有基因/病理时如实不做这一格"）：STS 恰好是**基因/病理高度决定入组**的病种——滑膜肉瘤看 `SS18::SSX`、去分化脂肪肉瘤看 `MDM2` 扩增、上皮样肉瘤看 `INI1/SMARCB1` 缺失，所以这四格（地区/亚型/分子/IHC）是真的，不是为显得专业硬塞的。

**指数口径（唯一允许的算法）**：

```
对每个维度 d：
  患者未知            → score = null，不进分母
  登记库该维为 null   → score = null，不进分母
  两边都有            → score ∈ [0,1]
index = round(100 × Σscore / count(score ≠ null))
若 count(score ≠ null) == 0  或  患者侧维度全为 null → index = null（只显示缺口）
```

**为什么加了"患者侧维度全为 null 也给 null"**（35 号未写、本项目实测补的）：招募状态是登记库侧事实，患者不需要提供任何东西。若让它单独支撑指数，一个什么都没填的档案会拿到 100 分，被读成"完全匹配"。实测反例见 `test/match.test.mjs` T9。
