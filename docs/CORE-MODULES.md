# 四个核心模块 · 小韧宝 SarcPal

> 目的：把「这个工作台为什么不是换个癌种名」压到四条可验收的模块上。
> 依据：`docs/DIFF-MATRIX.md`（肉瘤差异化种子）、`docs/SCENARIOS.md`（六条假设 + 孤儿页签对照 + 癌种额外断言）、`docs/SPEC.md`。
> 状态：**phase1 交付物，未经 G1/G2/G3 任何一道闸口签认。**
> 补件缘由：独立评审 P2-6 指出模板要求本文件而仓库缺件，「四核心模块完整」只能由评审人推定。本文件即按该要求补写，**不追认评审时的推定口径**（见文末 §五）。

## 一、判定标准

一个模块算「核心」，必须同时满足三条：

1. **离开软组织肉瘤就不成立**（换成乳腺癌/淋巴瘤/肺癌要么不成立，要么意义完全不同）；
2. **患者自己会反复用到**，不是把医生流程搬到界面上；
3. **有一个具体的失败后果**——做错了会让患者误解病情或做错决定。

按这三条从 12 个一级页（`app.js` 的 `PAGES`）里筛出四个。其余八页是必要构件，但不满足第 1 条或第 3 条，列在 §六「支撑模块」。

本项目**不使用 M01–M14 / AC-xx 编号**（肉瘤 SPEC 是叙述式，没有模块编号表），因此下文一律用「页面 key › 页签」与探针断言 ID 定位，不虚构编号。

## 二、核心一 · 病理与分型（`tumor` › 亚型与病理 / 部位与大小 / 分期与分级 / 分子检测）

**离开肉瘤为什么成立不了**
软组织肉瘤不是一种病，是一组间叶来源肿瘤的统称。同样大小、同样部位的两个肿块，
可能是完全不同的两种病，治疗与预后天差地别。所以「先定亚型，再谈别的」是肉瘤独有的顺序；
上皮癌里「先看部位和分期」的经验在这里会用错。

更独有的一条是**非计划切除**（unplanned excision / "whoops" 手术）：无痛肿块被当成脂肪瘤或囊肿切掉，
术后病理才回报肉瘤，于是要二次扩大切除。这是肉瘤特有的确诊创伤——患者带着「我已经被切过一次了，
是不是被耽误了」进场。**界面只记事实：「哪天在哪做过什么、病理什么时候回报」，绝不评价当初该不该切。**

**用户任务** 把一份看不懂的病理报告，变成「我属于哪一型、哪一级、我下次要问什么」。

**规则要点**
- **亚型 / 部位 / 分期 / 分级四个词分开摆，不互推**：产品**不**由分级算分期、**不**由部位推期别、
  **不**把亚型翻译成通俗名（`DIFF-MATRIX` 差异化种子第 2、3 条）。
- **FNCLCC 三个组件（分化、核分裂、坏死）照抄原文，不算总分、不折算 G**：分级结论是病理科写的，不是产品算的。
- **该部位没有分期组时必须能空着**：AJCC 第 8 版对头颈、胸腹腔内脏、眼眶**未定义分期组**
  （NCCN ST-5 原文：needs data collection before defining a stage grouping）。
  空态文案按部位分支：`stageEmptyLabel()`——腹膜后/腹腔/盆腔/胸腔/纵隔/头颈/眼眶/内脏 → 「该部位未定义分期组」，
  其余 → 「未回报」。**「未定义」和「还没出报告」是两件事，不能共用一句话。**
- **分子检测只记做了哪些、结果原文**；不写「哪些亚型该查什么」（那是判断）。

**验收** 探针 `X3j`（腹膜后档案写「该部位 AJCC 8 未定义分期组」）、`X3k`（有分期行的档案照抄 pT2N0M0，不出现「未定义分期组」）、
路径 A/B/C 的 `tumor/1` 步骤。原型已实现：四页签齐全、分期空态按部位分支、分级三组件原文展示。

**未核实** AJCC 8 与 WHO 第 5 版均**未取得原件**，页码一律待核；两处依据来自二次来源，已在 `DIFF-MATRIX` 与「?」疾病概要里分别标注。

## 三、核心二 · 手术与切缘（`surgery` › 手术档案 / 切缘记录 / 伤口与恢复）

**离开肉瘤为什么成立不了**
「切缘阴性 ≠ 切干净」这条在多数实体瘤都成立，所以它本身不够当理由（第一版没写清这层限定）。
肉瘤独有的是**切缘要放在「二次扩大切除」这个动作里读**：
- 第一次是**非计划切除**（当成脂肪瘤切了），那次手术的切缘**基本没有参考价值**，
  因为它切的是「一个良性的东西」，切到哪儿算哪儿；
- 第二次是**扩大切除**，这一次的 R0/R1/R2 与「距肿瘤多少毫米」才是真正决定要不要补放疗的依据；
- 而患者手上常常同时有这两份病理，两份都写着切缘——**分不清哪份算数，是肉瘤特有的误读**。

所以这个模块要做的是「把两份切缘按手术次序摆开、各自带日期与机构」，
而不是把「切缘阴性」翻译成一句更吓人的话。报告写「切缘未见肿瘤」不等于「切干净了、不用再治」。

**用户任务** 记住「哪次手术、切了什么、切缘原文怎么写的、伤口后来怎么样」，复诊时能原样复述。

**规则要点**
- **切缘只照抄原文**（R 分级、距离、部位），产品**不生成**「切干净了 / 切得干净 / 已切净」这类结论。
- **术式、切除范围、重建方式分三个字段**：肉瘤的「切除范围」与「重建」是两件事，合并会丢掉「切了但没重建」的情形。
- **手术档案主表单 ≤6 字段**，其余 6 项（术后诊断、麻醉、切缘原文、伤口情况、手术时长、出血量）折进「⋯ 更多字段」；
  时长与出血量用数字键盘（`input type=number inputmode=numeric`）。
- **写错不删**：记录详情「改这一条」→ 追加版本（改前值保留，删除=更正为作废）。
- **伤口记录是自述，不是并发症诊断**；拍照只作为附件，不生成任何判断。

**验收** 探针 `X3a/X3b`（每页显式写入口 ≤1，6 个写入口全在「⋯ 更多」内）、`X3c`（主表单 6 字段）、
`X3d`（数字键盘）、`X3l`（切缘页不出现「切干净」）、`X3g/X3h`（无裸删除、有更正链）。

## 四、核心三 · 治疗线序与放疗窗口（`treatment` › 线序时间轴 / 化疗周期 / 放疗 / 靶向与免疫）

**离开肉瘤为什么成立不了**
**第一版这里写错了，改掉。** 原文说「术前还是术后、多少 Gy、为什么停——这三问在乳腺癌语境里不成立」，
这句不成立：乳腺癌同样有术前/术后放疗、剂量与中止原因。拿乳腺癌当反例是把尺子用错了。

真正站得住的肉瘤专属理由是这四条：

1. **线序被「手术」切成两段，而手术本身可能是意外的**：非计划切除 → 二次扩大切除 → 术后放疗，
   患者的实际顺序里常常夹着一台「本来不该做的手术」。上皮癌的线序是「确诊→方案」，
   肉瘤的线序是「切了→才知道是肉瘤→再决定」，时间轴上第一个节点经常不是计划内的。
2. **术前 vs 术后放疗的选择由切缘与部位决定**：肢体肉瘤术前放疗是为了缩小照射野、保住肢体功能，
   术后放疗是因为切缘阳性但已经切了——**同一句「我做过放疗」，在肉瘤里必须先问它属于哪一段**，
   否则「放疗在前还是在后」这件事在时间轴上是模糊的。
3. **腹膜后与肢体的线序不是同一套**：腹膜后以整块切除 + 复发后再评估为主，
   肢体以保肢为核心、放疗与重建交错；同一癌种两个部位两条路径。
4. **靶向药的可及性按部位与线序分岔**（腹膜后 vs 晚期肢体），「获批状态未核实」必须逐条标。

**用户任务** 说清楚「我用过什么、第几周期、放疗起止与剂量、哪天因为什么停的」。

**规则要点**
- **线序按时间排，不按「一线/二线」编号**：患者的实际顺序常常不是教科书顺序（换药、暂停、加放疗），
  编号会把「跳过的线」变成空白，看起来像没治过。时间轴只记发生过的。
- **放疗记起止日期、部位、剂量原文**；不写「放疗有没有效」。
- **靶向与免疫的药物条目必须带「获批状态未核实」**：登记信息与说明书状态是两回事，
  产品不给「这个药适合你」的判断（`X3n`）。
- **周期取消/延迟只记原因原文**，不解释成「病情变化」，也不给处置建议。

**验收** 探针 `X3n`（药物条目带「获批状态未核实」）、路径 B `treatment/0` 与 `treatment/2` 步骤、`X1` 双向覆盖（37/37 可达、孤儿 0）。

## 五、核心四 · 功能与康复（`function` › 日常动作 / TESS 自评 / 康复记录）

**离开肉瘤为什么成立不了**
保肢手术之后的**肢体功能**是肉瘤独有的一条长期负担：切了哪块肌肉、重建了什么、胳膊还能抬多高，
直接决定日常生活。TESS（Toronto Extremity Salvage Score）是**肢体重建专用**的量表，
乳腺癌/肺癌工作台里没有对应的东西——它们的功能问题是疲乏与呼吸，不是「这只手还能不能梳头」。

**用户任务** 隔一段时间能自己作一次答，把「这半年手比以前笨了」这种模糊感受变成可对照的原始作答。

**规则要点**
- **TESS 按肢体算题数**：下肢 30 题、上肢 29 题，切肢体必须同时改题数与 `aria-pressed`。
  （修前这个切换是失效的：`render()` 只重建 `#main`，不改已打开的整页视图；已修，见 `INTERACTION-DESIGN` §六 第 2 条。）
- **逐题记录原始作答，不算总分、不做趋势判读、不给「功能好转/变差」的结论**：量表分值是研究工具，
  患者自己看总分只会得到一个没有意义的数字。
- **不引用 MSTS 评分**（`X3m`）：本项目没有取得 MSTS 的原始表格与中文口径，引一个没核过的评分体系比不引更糟。
- 日常动作页只记自述（「今天能不能自己扣扣子」），不做能力分级。

**验收** 探针 `X3m`（功能页不出现 MSTS）、`X3p`（切上肢 30→29 且 `aria-pressed` 翻转）、路径 B `function/1` 步骤。

| 页面 | 为什么不是核心 | 备注 |
| --- | --- | --- |
| `dashboard` 看板 | 是入口面，不是业务模块 | 三件事：资料在哪、今天补哪条、复诊带什么 |
| `diagnosis` 确诊路径 | 服务核心一（把非计划切除的事实按日期排好） | 不独立成模块 |
| `tox` 副作用与不适 | 换成任何癌种都成立 | 只记原话与门诊记录原文 |

| `followup` 复查与随访 | **表单是通用的，但档位不是**：复查间隔按部位分五档（`EXTSARC-2~5` / `RETSARC-3`，「腹膜后跟肢体不是一张表」），这一层肉瘤特异性是真的。降级理由不是「通用」，而是：**它属于核心一（病理与分型）的验收面**——部位定分成哪一档，先得有部位；单列成模块会把「档位从哪来」这件事从核心一里拆走 | 影像并列 + 指南原文 + 问题清单。第一版写「通用构件」是误判，评审指出后改正 |

| `life` 生活与照护 | 换成任何癌种都成立 | 异地就医、花费、照护者、体重 |
| `trials` 临床研究 | 通用构件 | 登记状态一律「未核实」，不作入组判断 |

## 七、与评审推定口径的差异（不追认）

`docs/DESIGN-REVIEW.md` 检验单第 5 项在没有本文件的情况下，按 12 页结构**推定**四模块为
「病理与分型 / 治疗与线序 / 影像与随访 / 生活与照护」。本文件按 §一 三条判据筛出的结果是
「病理与分型 / 手术与切缘 / 治疗线序与放疗窗口 / 功能与康复」，两处差异及理由：

- **影像与随访**：影像时间轴与随访节奏换成任何癌种都成立，不满足第 1 条 → 降为支撑模块。
- **生活与照护**：同上 → 降为支撑模块。
- **手术与切缘**：肉瘤的局部控制核心，且「切缘阴性 ≠ 切干净」是具体误解风险 → 满足第 3 条。
- **功能与康复**：TESS 是肢体重建专用量表，换癌种不成立 → 满足第 1 条。

**这不是「评审审错了」，而是评审在缺件状态下只能推定。**

**一处必须更正（评审 N6，本文件第一版是过度声明）**：原文写「四模块各有独立一级页 + 写入口或整页视图，成立」——
对核心一**不成立**。`tumor` 是独立一级页、四个页签齐全，但**没有整页视图、没有新增写入口**，
患者只能看只读记录并点「改这一条」（`INTERACTION-DESIGN.md` §3.2 自己也写「无手工新增入口」）。
准确的表述是：

| 模块 | 一级页 | 整页视图 | 新增写入口 | 更正入口 |
| --- | --- | --- | --- | --- |
| 核心一 病理与分型 | ✅ `tumor` | ❌ | ❌ | ✅「改这一条」 |
| 核心二 手术与切缘 | ✅ `surgery` | ✅ `data-pv="surgery"` | ✅（菜单内「＋ 记一条」） | ✅ |
| 核心三 治疗线序与放疗窗口 | ✅ `treatment` | ✅ `data-pv="timeline"`（按钮文案「打开线序全景（整页）」） | ❌（本轮只读） | ✅ |
| 核心四 功能与康复 | ✅ `function` | ✅ `data-pv="tess"` | ✅（「＋ 记一次」） | ✅ |

是否给核心一与核心三补整页写入口，属 **M6 决策**，不是 G1 范围；这里只把话说准，不补功能。

**复评对论证的三点保留，照实记下（不装作已全接受）**：

1. **核心三的四条理由里只有两条硬**：第 1 条（线序被一次意外手术切断）与第 3 条（腹膜后 vs 肢体两套路径）是肉瘤专属；
   第 2 条（术前 vs 术后放疗）与第 4 条（靶向按线序分岔）在乳腺癌同样成立，只能算辅助。
   结论：**模块保留**（第 1、3 条足以支撑「离开肉瘤不成立」），但四条不等于四条都硬。
2. **核心二「基本没有参考价值」说得过满**：非计划切除的切缘不是没有价值，而是**不能直接拿来决定要不要放疗**——
   它对应的瘤床需要按第二次扩大切除的标本判。已按此理解使用，措辞不再作「无价值」解。
3. **`followup` 的降级理由仍需留意**：「属于核心一的验收面」是**归并范围**的说法，不是判据本身——
   按本文件 §一 三条判据，`followup` 满足第 1 条（档位按部位分五档）与第 3 条（档位错了会让人按错间隔复查），
   只是它不构成独立模块。这一点记在这里，避免下一轮把它读成「通用构件」。
