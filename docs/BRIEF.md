# 需求起点

来源：初始化配置。用户、场景和流程是有效的SPEC互动素材；继承会话中已有明确确认，其余不能仅因配置通过校验就当成设计定稿或研究验证。

目标用户：软组织肉瘤（含肢体/躯干、腹膜后、头颈等部位）患者与照护者；以术前评估—术后康复—长期复查三段旅程为主，也覆盖晚期治疗与随访。

场景：肉瘤确诊常走弯路：无痛肿块被当作脂肪瘤或囊肿，切了才在病理里发现是肉瘤，于是要二次扩大切除。之后的每一步都分散在不同医院——病理会诊在一家、手术在一家、放疗在一家、复查在一家。患者手上是十几份报告、几张影像光盘和一堆说不准确的日期。工作台做的事是把这些放回一条时间轴上：哪天做过什么、报告原文怎么说、自己哪里不舒服，需要问医生的问题是什么。

核心流程：
1. 打开工作台，先看今天：最近一次复查是什么时候、下一次大概在什么时候、有没有还没问医生的问题
2. 把一次就诊或一份报告归档进去：日期、机构、类型、原文留档，核对后入库
3. 看化验与指标：血象、肝肾、炎症这些数值按时间连成线，看得到每次的参考范围
4. 把治疗线序与副作用对上：哪条线用的什么方案、第几个周期、当时记下什么不适（照抄报告与自己的原话）
5. 复查前整理：影像时间轴 + 问题清单，带着去门诊

完成结果：一次门诊前，患者能在同一屏里找到：上次影像什么时候做的、报告原文怎么写、这期间记了哪些不适、要问医生哪三个问题；全程不出现任何"你这属于什么期/该不该换药"式的判断。

初始布局选择：business-first
